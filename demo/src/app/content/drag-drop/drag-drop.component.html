Drag and drop

Angular has no built in drag and drop for svg elements - instead, we must use mouse down to discover the selection of an element, then move it while the mouse moves and finally stop the drag when the mouse moves up again. However, we need to make sure that we can also detect a click and a double-click and that these events do neither interfere with each other nor with drag and drop. Hence, this section is concerned with all types of mouse events.

Dragging

There is an explicit draggable svg component. This base component makes sure that drag events are correctly reported to the SVGAccessService. It is supposed to be extended by an own svg component with an own template. This own component must provide an element that satisfies the interface `draggable`.

The base component provides an SVG template with the required mouse-event bindings. It has no visual representation of its own; applications extend it with a component containing their own SVG template. As for our extending component, its template shows a small rectangle that we can drag. Clicks trigger a color change for the rectangle.

Please note, that position and color changes are not read back into the form - this is due to Angular's value copying: the form value is the driver, whose changes ARE reflected in the object, but object changes do not read back into the control. We added an extra binding to trigger a complete form patch on every click (color change) - it would be possible to also detect position changes via the svgAccessService and read that back as well.
