Diagram Playground

This interactive playground lets you explore EMFular-diagram v1.x concepts, services, and components. We currently offer a detailed description of the available mouse event handling and arrows but plan to extend the playground for the graphical base components and the canvas as well.

Angular with SVG-Templates

Angular is so attractive for svg-based diagrams, since components can have SVG instead of HTML templates. There is a short explanation by Angular, but as of August 2026, it does not cover cases, where a component is part of a bigger svg. In order to compose one svg of svg-components, you need to know a few things:

  • Angular components are always HTML elements unless hosted on a real SVG element. Therefore, every SVG component must be attached to an svg group (selector 'g') or an other SVG element. You also need to write the component selector for 'my-component' as [my-component]. Only then, others can write <g my-component> ... <g/> to use it within their svgs.
  • Even though your template ends on svg instead of html, the component contents will only live in the svg namespace, if you use <svg:g> .. </svg:g> and not only a "g" as top level element. Once, the namespace is established, you can use any svg-primitive inside without the extra 'svg:'.
  • Angular treats many SVG properties differently from HTML ones. Most SVG fields, like x, y, cx, d, and, transform, are attributes and must be bound with attr.x, attr.transform, etc. Property binding ([x]) only works for attributes that Angular knows as DOM properties.
  • SVG attributes are case-sensitive, while HTML is not - so pay attention to casing.
  • If you ever export your svg, make sure that all component styles are svg-styles, not normal css. The latter will not be transferred into the downloaded svg.
  • If you ever mix HTML inside SVG via 'foreignObject' (e.g. for text inputs), Angular's change detection works, but exporting the SVG will drop all HTML content. Don't worry: We have a text component that also provides an svg text underneath to transport it.

The Drawing Canvas

Each svg-component needs to live inside one top level svg element, that opens the svg-namespace inside HTML. We provide a drawing canvas, that only defines the absolutely necessary viewBox and offers a content projection slot for the svg-components that it should display. Again, projected top-level elements must provide "svg:g", not only "g".
