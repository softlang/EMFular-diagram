Arrows

We are currently offering only direct arrows between two points, no multilines or curves. Depending on how you want to specify these points, you can choose between these components:

Arrows between Points

Explicitly given points are the easiest and cheapest way to define arrows. The arrow adapts as soon as its input point changes. So make sure that this happens, e.g. when moving the object around.

Arrows between Bounding Boxes

It is also possible to let arrows compute best matches for points based on a given bounding box. The best matching point will always be on the segment closest to the other bounding box. Since bounding boxes are all aligned, the fitting segmets are always parallel lines. If their projections onto the same line overlap, the bets point is the middle of the overlap, otherwise, the two edges closest to each other are used.

Arrows between Elements

It is also possible to define an arrow as connector between two elements, given by their IDs (that is the id attribute of the svg element). The component will then compute bounding boxes for both elements and then find best points to connect them.

Be aware that the computed arrow attachment happens on the bounding box, so it might look strange if your shape is far from that box (see triangles below for examples).

Arrow Styling

Arrow styling is mainly driven by the following interface:

Color is any string you could put into the corresponding style attribute, and strokeDashArray corresponds to the stroke-dasharray that many svgs support, e.g. '4 1 2' - but please specify [4,1,2] for the array. You can add arbitrary inline styles via the extra style-Attribute. For details on allowed attributes, consider MDN. We ensured that the explicit style configuration has precedence, if you specify it. Please do NEVER use external css to control svg behaviour, since it will not be exported with the SVG.

Arrow Pointers

SVG lines can support three pointers: start, end and middle. We currently only support start and end (since we have no poly-lines). These pointers must be provided as markers, defined at the beginning of the SVG in the defs-section, and then referenced at each usage. In order to support this mechanism, the start- and endPointers are just strings, that is the ids of defined markers. Hence, arrow tips will only work, if you also provide a marker definition.

Defining Markers

Markers are available, if you have marker definitions inside the svg:defs section.

If you use arrow tips, make sure to add the respective defs section at the beginning of your svg.

Adding Text

You may also add text to an arrow, by using the optional text attribute. Be ware, text that is longer than the arrow line, will not be visible. You can control text style attributes via two optional inputs, textStyle and textPathStyle. For more details on available attributes, please consider the official style guides, e.g. MDN.

Arrow Adaptation on External Movement

If your arrows attach to bounding boxes or elements, the arrow's automatic change detection will only realize if the underlying position is replaced, but not if its coordinates changed.

Arrow Notification on Arrows Between Elements

Arrows between elements listen to the `svgAccessService`, to see changes of one of the relevant ids for start and end. The service gets notified about position changes and communicates them to all subscribers. For drag-based interactions, we strongly suggest that you use the input-draggable-component as basis, so that this service is already correctly wired in.

You can see that all drag events are indeed correctly seen but that the double click event that changes the position of the box is not captured, unless we notify the service manually. You can activate this notification in the control and will see it afterwards on every double click induced position change. If you have any methods that could change an object's position, notify the svgAccessService of these changes for the arrow to see the change.

Arrow Notification on Arrows Between Boxes

The box offers no such mechanism "out of the box" ;)
Please use an mechanism to re-assign the position, so that a change is detected, e.g. by creating a new object and reassigning the former content. An example for that is `elem.position = {...elem.position};`.
