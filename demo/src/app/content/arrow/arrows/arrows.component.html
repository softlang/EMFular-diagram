Arrows

We are currently offering only direct arrows between two points, no multilines or curves. Depending on how you want to specify these points, you can choose between these components:

Arrows between Points

Explicitly given points are the easiest and cheapest way to define arrows. The arrow adapts as soon as one of its input coordinates changes.

Arrows between Bounding Boxes

It is also possible to let arrows compute best matches for points based on two given bounding boxes. The best matching point of each box will always be on the segment closest to the other bounding box. Since bounding boxes are all aligned, the fitting segments are always parallel lines. If their projections onto the same line overlap, the best point is the middle of the overlap, otherwise, the two edges closest to each other are used.

Arrows between Elements

It is also possible to define an arrow as a connector between two elements, given by their IDs (that is the id attribute of the svg element). The component will then compute bounding boxes for both elements and then find best points to connect them.

Be aware that the computed arrow attachment happens on the bounding box - you can see this on the scaled and rotated rectangle and when connecting both triangles.

Arrow Styling

Arrow styling is mainly driven by three interfaces, one for the main arrow (shown below) and two more that we explain when discussing text on arrows, since the control text styles and text path. Each style is accompanied by a directive so that lib users can easily apply a style to their own components. The styles are bound as attr-bindings, making them native svg, so that they are exported with the svg.

Color is any string you could put into the corresponding style attribute (stroke), and strokeDashArray corresponds to the stroke-dasharray that many svgs support, e.g. '4 1 2'. For details on allowed attributes, consider MDN. Please do NEVER use external css to control svg behaviour, since it will not be exported with the SVG.

Arrow Pointers

SVG lines can support three pointers: start, end and middle. We currently only support start and end (since we have no poly-lines). These pointers must be provided as markers, defined at the beginning of the SVG in the defs-section, and then referenced at each usage. In order to support this mechanism, the start- and endPointers are just strings, that is the ids of defined markers. Hence, arrow tips will only work, if you also provide a marker definition.

Defining Markers

Markers are available, if you have marker definitions inside the svg:defs section. If you use arrow tips, make sure to add the respective defs section at the beginning of your svg.

Adding Text

You may also add text to an arrow, by using the optional text attribute. Be ware, text that is longer than the arrow line, will not be visible. You can control text style attributes via two optional inputs, textStyle and textPathStyle.

There are more attributes that you can manually bind via attr-binding, but we only used those we considered broadly relevant for our interfaces and the corresponding directives. Especially, the interplay of textAnchor and startOffset might help on arranging text.

Arrow Adaptation on External Movement

If your arrows attach to bounding boxes or elements, the arrow's automatic change detection will only realize if the underlying input is replaced, but not if its coordinates changed.

Arrow Notification on Arrows Between Elements

Arrows between elements listen to the `svgAccessService`, to see changes of one of the relevant ids for start and end. So make sure that any component that you control notifies the service about movements, and that every component that needs to adapt, subscribes to its notifications and filters on relevant elements. Our drag directive already communicates its position changes (both to the service and locally via an output), but we have no control over your self-written components.

In the example below you can see that all drag events are indeed correctly seen but that the double click event that changes the position of the box is not captured, unless we notify the service manually. You can activate this notification in the control and will see it afterwards on every double click induced position change. If you have any methods that could change an object's position, notify the svgAccessService of these changes for the arrow to see the change.
